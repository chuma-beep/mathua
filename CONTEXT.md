# Mathua — Domain Language

> Derived from `improve.md` gap analysis + Q1-Q3 locks (Lesson/Study/Profile/Seam/effort XP, 50 XP quiz). Used by `grill-with-docs`, `tdd`, `domain-modeling` to name seams and tests.

## Language

**Concept** — Atomic node in the DAG (`internal/concepts/concepts.go:8` `id/label/domain/subdomain/prerequisites/mastery_threshold`). Example: `frac.add.word` (`data/concepts/fractions.json:149`, 25.0s).  
_Avoid_: topic (MA), lesson (maps to corpus, not node)

**DAG** — Directed acyclic graph of Concepts. Hard rules: prereqs mastered before surface (`internal/concepts/concepts.go:73` `Available`), Kahn's topo order, `scripts/validate_graph.go` rejects cycles/orphans.  
_Avoid_: graph alone, knowledge map

**Lesson (corpus / worked example)** — Inline worked example per KP, 10× granularity vs textbook (`improve.md:39` 300 topics ×3 KPs). Q1 locked: Lesson is corpus, not library. Rendered via `KatexContent` (`web/next-app/app/study/page.tsx:592`) before practice. Source: `data/lessons/lessons.json:1` `teaching/*.md` + `algebrica/*.md` (`README.md:177`).  
_Avoid_: Study, chapter

**Study (library)** — Browseable corpus library (`web/next-app/app/study/page.tsx:1` `LessonDetail/DomainOverview`). Q1 locked: Study stays library label, not landing. Holds `Lesson` + `LessonQuiz` (`study/page.tsx:596`) but does not gate progression.  
_Avoid_: Practice, Learning Mode (removed `web/next-app/app/session/page.tsx:1` chooser)

**Profile (hub)** — Universal landing for guest + authed (`web/next-app/app/profile/page.tsx:44`). Guest gets ephemeral `mathua_guest_id` (`web/next-app/lib/auth.ts:4` `ensureGuestId`). Shows `ProfileStats`, `DomainProgress`, `StrugglesSection`, `ActivityHeatmap`, and `Diagnostic CTA`. Post-auth always → `/profile` (`login:165`, `onboard:186`, `goals:224`).  
_Avoid_: dashboard alone, account page

**Diagnostic (frontier)** — Adaptive CAT finding knowledge frontier (`internal/diagnostic/cat.go:1`, `improve.md:27` 30–45 min, covering set + info-gain). Entry: `/onboard` welcome (`onboard/page.tsx:56`), CTA on `Profile` (`profile:209`) labelled `Recommended` vs `Retake` (`profile:209`).  
_Avoid_: test, assessment, quiz (reserved)

**Seam** — Public boundary to test at (`tdd` `skills/skills/engineering/tdd/SKILL.md:1`). Pre-agreed seams for next bite: `LessonQuiz → SubmitAnswer` (`internal/engine/engine.go:398` `POST /api/answer` `server.go:286`).

**TaskLesson / TaskReview / TaskMultistep / TaskQuiz** — XP task types (`internal/xp/policy.go` effort-derived bases). Q2 locked: `*.word` and plain share the effort calibration (thresholds already differ); reviews cost half; quiz adds an assessment premium.  
_Avoid_: flat per-question XP, word as separate prereq depth (temporary node, future `Variants` fold via `enrichment.json` `improve.md:114`)

**Quiz (50 XP gate)** — Q3 was MA-verbatim `150 XP` (`improve.md:27`); rescaled to `50 XP` with the small-awards economy (same ~5-lesson cadence, smaller numbers — user-tuned economy supersedes MA fidelity, see ADR-020). Timed closed-book, `80%` difficulty via `computeDifficulty`, diverse recents, immediate remedial + retake (`internal/quiz/quiz.go:1`). Daily goal `10` (drift fix shipped: versioned backfill in `sqlite.go`). Banner: `Study → Take Test` + `Profile` due-reviews.
_Avoid_: 1–2 lesson gate, 30 XP shortcut

**XP** — `Award` in `internal/xp/policy.go` (`EffortBase 1–5 × timeMult 0.5–1.25 × streakMult 1+0.05*streak`): an effort-derived approximation, never exact time accounting. Miss 0, rush −1, diagnostic 0 XP. Daily goal `10`. Verified via `go vet` + `learn → answer → profile` `playwright`.

**GUEST_KEY** — `mathua_guest_id` persisted so guest `/profile` survives reload (`lib/auth.ts:4`).

**Landing graph (hero)** — WebGL concept map on `/` (`components/MathConceptGraph3D.tsx`), fed by build-time artifacts `public/data/concepts.graph.json` (nodes + indexed edges + domain counts) and `public/data/concepts.positions.json` (quantized `[x,y,z]`), generated by `scripts/build-graph.mjs` (`npm run graph:build`, also via `prebuild`). The corpus `data/concepts.json` stays out of First Load JS; only `data/graph.meta.json` (counts) is bundled. LOD tiers (far/mid/close) derive from world-units-per-pixel; labels render in one imperative DOM overlay; focus mode dims non-1-hop nodes/edges but never removes them.  
_Avoid_: bundling `concepts.json` into the landing bundle, per-node DOM/event listeners, client-side force layout

## Relationships

- DAG holds many Concepts; Concept has Prerequisites; `Available` filters by mastered
- Profile holds Progress/Scores/Weakness/Activity; Study holds Lessons; Lesson holds Concepts + Problems
- Diagnostic compresses DAG → picks Concept via info-gain; Post-diagnostic → Profile
- Study Lesson `→` TaskLesson (or TaskMultistep if `.word`) `→` SubmitAnswer `→` XP/Progress `→` Profile; at 50 XP `→` Quiz (TaskQuiz)

## Flagged ambiguities

- `Learning Mode` infinite loop removed (`session` now chooser `session/page.tsx:1` Diagnostic vs Study, then `Profile` hub); do not reintroduce as primary
- `Study` links that were wrong post-login (`login Skip → /study` etc) fixed to `→ /profile`; do not regress
- `skills/CONTEXT.md` is marketplace language (Issue tracker) — not Mathua; Mathua context lives here

## Decisions (ADRs, inline)

- ADR-001 Q1: Lock `Lesson=corpus`, `Study=library`, `Profile=hub` (2026-08-29) — prevents catalog-as-path relapse
- ADR-002 Q2: `*.word` as `TaskMultistep 15` seam, keep separate node pending `Variants` fold (2026-08-29)
- ADR-003 Q3: Quiz gate `150 XP` MA verbatim, not lesson-count shortcut (2026-08-29) — daily goal `30` makes `150/30=5d` honest — SUPERSEDED by ADR-020 (small-awards rescale, same cadence)
- ADR-004 Landing graph: keep three.js/R3F, drop drei; fetch graph payload/positions instead of bundling the corpus; deterministic domain-sector spherical layout (`lib/layoutDAG3D.ts`, O(n log n), 5k nodes ≈24ms); demand frameloop with auto-rotate stopping after first interaction (2026-09-11) — mobile First Load JS and 1k–5k scale without a renderer migration
- ADR-005 Grading contract (2026-09-27): one canonical dispatch `Engine.GradeAnswer` = custom `GradedGenerator.Grade` → 9-type `Router` (6 pure-Go graders) → SymPy. Every server path (`/api/answer`, `/api/study/answer`, quiz, goal diagnostic) must use it; a bare router call mis-grades the 32 custom-grader concepts (`5 R 3`, `3 sqrt(2)`, matrices, ratios). SymPy ships in the image (pinned `grading/requirements.txt`) and the image build self-tests, so `symbolic`/`polynomial`/`expression`/`complex` grading is present in production; there is **no** pure-Go symbolic fallback (the old `symbolicGrader` is dead code). Go fast paths grade exact-equal and constant-value expressions without the subprocess. Consequence: `expected == answer` must always grade correct.
- ADR-006 Grading never penalizes an infrastructure fault (2026-09-27): a grader that cannot run is "ungraded", never a student miss — no attempt, streak reset, weakness bump, or XP. `grader.Result.Unavailable` marks it. (The prod outage recorded ~32% of concepts as false misses because a missing SymPy runtime returned `correct:false`.)
- ADR-007 Study anchor is per-question (2026-09-27): practice stores the expected answer for **every** served question (keyed by question text, `SetStudyExpectedBatch`), not just the first. Anchoring only `questions[0]` guaranteed a mis-grade for any later question.
- ADR-008 Placement never destroys mastery (2026-09-27): `ApplyGoalResults` seeds only concepts still `UNSEEN`; a diagnostic/plan run must not overwrite streak, SM-2, attempts, or mastery of a concept the student has already started.
- ADR-009 Every served `Question` carries `grading_type`; every answer host shows the matching input (study, review, quiz, diagnostic). `Engine.GradeAnswer` is the one grader; `Result.Unavailable` is fail-soft everywhere (no attempt/streak/XP; client retries). `AvgResponseTime` includes incorrect attempts. `*.word` is `TaskMultistep 15` in both practice and study (implements ADR-002). Deferred: no repository transaction wraps progress+attempt+XP yet, and the study seam still accepts a client `expected` as a fallback when no server anchor exists.
- ADR-010 Grading data repair (2026-09-27): `mathua -repair-grading[-dry-run]` re-grades persisted `attempts` with `Engine.GradeAnswer`, flips false negatives (`UpdateAttemptCorrect`), and rebuilds `concept_progress` by replaying corrected history with the mastery/SM-2 primitives. `Result.Unavailable` attempts are skipped; XP is not rewritten. Always dry-run first.
- ADR-011 Structured choice input (2026-09-27): `multiple_choice` questions whose option list is embedded as `A) …` blocks (`lib/choices.ts` `parseChoices`) render tappable options (`components/ChoiceOptions.tsx`) in every answer host (diagnostic, quiz, review, study); picking one submits the option text, which `choiceGrader` grades by exact match. Non-parseable MC and all other types keep the free-text input. `SymbolPalette` gains a space key and the numeric hint names the fraction/mixed-number formats, so `4 1/10` is enterable on mobile. A server-side `Options` field on `generator.Problem` (rather than parsing the stem) is the intended follow-up.
- ADR-012 Postgres is a first-class store (2026-09-27): `internal/storage/parity_test.go` runs one identical scenario against SQLite and Postgres and requires the same observable result; CI runs it against a `postgres:16` service and `deploy` depends on it (`TEST_POSTGRES_DSN` gates the test). The parity test caught `GetDailyActivity` comparing a TEXT `timestamp` to `timestamptz` — now cast with `::timestamptz`. Known remaining divergence: Postgres `attempts`/`active_sessions` omit the SQLite foreign keys (align in a later pass).
- ADR-013 Corpus counts are generated, not hand-written (2026-09-27): `scripts/counts.py` computes concepts/domains/KP files/KP entries/subgoals/courses/diagrams from `data/` and rewrites the README's badges, sentences, and domain table (`--write`). CI and `make validate` run `--check`, which fails on stale README counts and on a denylist of superseded numbers (`641`/`580`/`284`/`1923`) anywhere in the docs. Counts had drifted every content wave; they now cannot.
- ADR-014 One diagnostic route (2026-09-27): the legacy `/api/diagnostic` + `/api/diagnostic/answer` (unauthenticated, trusted a client `correct` flag, no persistence, unused by the frontend) is removed, along with `Engine.SubmitDiagnosticAnswer`. `/api/goal/diagnostic/*` is the only diagnostic: it grades server-side via `Engine.GradeAnswer` against the stored problem. The legacy end-to-end test was migrated to the goal route.
- ADR-015 Stub lessons fail the gate (2026-09-28): 9 committed lessons were SEO/placeholder stubs (5 Algebrica bodies that never landed, 4 fraction word-problem templates); the audit only scanned `teaching/*.md` non-recursively and never `algebrica/`, so it missed all of them. The gate now scans recursively and flags tiny word-count + boilerplate files, validated to zero false positives against the corpus. Remedy: refetch Algebrica bodies via `scripts/refetch_algebrica.py` (one-time network, then committed), author word lessons to match their KP sections, and repoint semantically wrong mappings (`alg.systems.elimination`/`substitution` pointed at the Rouché–Capelli theorem page) with rewritten KPs. One lesson serving many concepts stays legal; the gate checks sections resolve, not 1:1 files.
- ADR-016 Currency-vs-math in the canonicalizer (2026-09-28): a `$…$` span with a digit is prose (escaped to literal `$`) only when it has no math marker and is either purely numeric or spaced *with a letter* (wordy price pairings like `$5 … saves … $10`). Factorial `!` is a math marker, and letterless lists (`1, 2, 3`) stay math — the old space-only rule leaked literal `$7!$`/`$1, 2, 3$` text into 24 lessons. Bare numerals (`$1$`) stay escaped per the bare-numeral gate; fix those in content, not here.
- ADR-017 Adaptive lesson loop (2026-09-29): `/learn` hosts the KP-interleaved loop; `Study` stays reference library, `Profile` task shelf deep-links to `/learn`. Pilot `Explanation`s (`arith.add`, `arith.div.remainder/long`, `frac.add.diff`, `frac.mixed.convert`, word variants) rewritten Given→Steps→Answer with substituted numbers. Prereqs are a soft dismissible banner via `GET /api/lessons/{id}/readiness` (no auto-redirect). Mastery is derive-only (`Engine.MasteryPct` + `MasteryBand`, no migration). Practice takes `?seed=&exclude=&difficulty=` so misses serve staged fresh variants. `mapping.json` kept (ingest scripts still read it).
- ADR-018 Attempt-first feed + task shelf (2026-09-29): `LearnStepper` is append-only — intro once, then each submit locks its card inline and the next question opens below; scrollback is the history, with a sticky tally header. No hint button and no gating buttons: post-mistake explanations render in the locked card, halt is a 3-miss safety net that appends an easier question plus prereq links. `masteryEstimate` (accuracy recent-weighted × difficulty × variation × time) drives advance/continue/intervene; 2-in-a-row is one input, not the rule. `selectShelf` proposes ≤5 eligible tasks behind a `SelectionPolicy` (v1 fixed weights: frontier-new, due review, weakness; XP shown per card); learner disposes. UI never names selection internals; critical path stays internal.
- ADR-019 Destinations + honest estimates (2026-09-29): destinations are named course bundles resolved to union prerequisite closures (graph stays source of truth); plans persist evidence/snapshots in `server_sessions(kind=study_plan)`, frontier derives live and is never stored. `internal/xp` owns award math (effort-derived 1–5 bases × time × streak; miss 0; rush −1; diagnostic 0 XP) and the estimator imports it — estimates can never duplicate constants. `EstimateWorkload` prices XP + time tracks (don't-knows cost reduced time with full remaining work, floored against gaming; quizzes/diagnostics are time-only, never XP debt). Pace is `min(goal, trailing-14d adherence)`; dates render as months, never promises. Goal changes never move quiz eligibility or mastery. Deferred: enforced per-path budgets, exam entity, CAT diagnostic, scored shelf policy, full misconception taxonomy.
- ADR-020 Small-awards economy (2026-09-29): XP rescales from flat 10/5/15/20 to effort-derived 1–5 bases (`EffortBase` from threshold seconds × difficulty; review halves, quiz premium +1); quiz gate 150→50, daily default 30→10, rush −5→−1, existing goals rescaled /3 via versioned v3 backfill (both stores). Cadence preserved (~5 lessons per quiz, ~a lesson a day). Bases are an effort-derived approximation, never exact time accounting. Deferred: retry multiplier, lesson accuracy bonus, continuous time-ratio rush.
- ADR-021 Study is reference-only detail (2026-09-29): LessonDetail shows title, concept chips, slim prereqs (badge + not-started/in-progress/mastered words, no percentages — percentages stay in Profile), one collapsed "Worked examples (N)" group (first expanded, identical bodies rendered once with combined labels, no pointer links), per-block ⋯ report menus with auto-attached block ids, and Start-learning CTAs. Footer, quiz banner, embedded practice, and the scroll-back button are gone from `/study` + `/concept`. No hidden results, no doing: reference explains, Learn teaches. Diagnostic prompts show iff new (`concepts_mastered === 0`) and incomplete, everywhere the rule applies.
- ADR-022 Reset clears evidence, keeps choices (2026-09-29): `Repository.ResetProgress` wipes progress/SM-2/speeds/attempts/sessions/quiz completions, study-scoped KV, XP, diagnostic flag, and league fields in one transaction on both stores; account, credentials, avatar, settings, goal, course, and `study_plan_prefs` (destination/deadline/pace) survive. Legacy single-record plans migrate lazily and idempotently. `POST /api/account/reset` requires the typed phrase, clears engine memory, orders the KV clear last, and is retry-safe. Settings danger zone gates on the phrase, offers CSV export first, and names the keeps (incl. leaderboard zeroing). Post-reset plans show a neutral fresh-start state until a new baseline lands.
- ADR-023 Single Next head over a ranked shelf (2026-09-30): supersedes the navigation model of ADR-017/018/021 (reference/doing split stands). DAG + `NextSmart` stay the source of truth; `selectShelfHead` returns `{next, alternatives}` with item 0 as the committed head, `selectShelf` is a flat wrapper, `selectNextUp` is the empty-policy fallback. `Learn` owns the head (`NextUpCard`); `Profile` shows a compact summary linking to `/learn`; `LearnStepper` done re-fetches the head and advances via `Continue: {label}` click (no auto-advance, alternatives present). `/concept` redirects to `/study?concept=`, `/session` redirects to `/learn`; nav `Start` renamed `Learn`. Study lists lessons in Kahn topo order. `TaskShelf` deleted.
