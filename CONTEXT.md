# Mathua — Domain Language

> Derived from `improve.md` gap analysis + Q1-Q3 locks (Lesson/Study/Profile/Seam/effort XP, 50 XP quiz). Used by `grill-with-docs`, `tdd`, `domain-modeling` to name seams and tests.

## Language

**Concept** — Atomic node in the DAG (`internal/concepts/concepts.go:8` `id/label/domain/subdomain/prerequisites/mastery_threshold`). Example: `frac.add.word` (`data/concepts/fractions.json:149`, 25.0s).  
_Avoid_: topic (MA), lesson (maps to corpus, not node)

**DAG** — Directed acyclic graph of Concepts. Hard rules: prereqs mastered before surface (`internal/concepts/concepts.go:73` `Available`), Kahn's topo order, `scripts/validate_graph.go` rejects cycles/orphans.  
_Avoid_: graph alone, knowledge map

**Lesson (corpus / worked example)** — Inline worked example per KP, 10× granularity vs textbook (`improve.md:39` 300 topics ×3 KPs). Q1 locked: Lesson is corpus, not library. Rendered via `KatexContent` (`web/next-app/app/study/page.tsx:592`) before practice. Source: `data/lessons/lessons.json:1` `teaching/*.md` + `algebrica/*.md` (`README.md:177`).  
_Avoid_: Study, chapter

**Study (library)** — Browseable corpus library (`web/next-app/app/study/page.tsx:1` `LessonDetail/DomainOverview`). Q1 locked: Study stays library label, not landing. Holds `Lesson` + `LessonQuiz` (`study/page.tsx:596`) but does not gate progression.  
_Avoid_: Practice, Learning Mode (removed `web/next-app/app/session/page.tsx:1` chooser)

**Profile (hub)** — Universal landing for guest + authed (`web/next-app/app/profile/page.tsx:44`). Guest gets ephemeral `mathua_guest_id` (`web/next-app/lib/auth.ts:4` `ensureGuestId`). The hub **and** the learner's own report: `ProfileStats` identity, `PositionBlock` (*where you are* — mastered / unlocked / locked plus the frontier the scheduler would serve next), the `NextUpSummary` task, the alerts (paused / reviews due / quiz gate / diagnostic), the new-user block, then the report — `Activity` (`ActivityHeatmap`) → `By domain` (`DomainProgress`) → `How you're doing` (the learner's own first/second-pass and attempts) → `StrugglesSection` → recently unlocked. Cohort figures (`total_students`, `retention_rate`, weekly first-pass) stay on `/docs/efficacy`, never here. Post-auth always → `/profile` (`login:165`, `onboard:186`, `goals:224`).  
_Avoid_: dashboard alone, account page, a separate progress page (there isn't one — ADR-025)

**History** — Every question the learner has answered (`web/next-app/app/history/page.tsx:1`), rendered by `AttemptList` (shared with the public token-based share report at `/share`). Defaults to the `Missed` filter; filterable by source; paginated. Was `/progress-card`, and the sidebar entry was called `Progress` while resolving here — a label pointing at a mistake log. Both are fixed: the rail reads `History` and the report lives on `/profile`.  
_Avoid_: progress, progress card, transcript (fine in prose, not in a route)

**Diagnostic (frontier)** — Adaptive CAT finding knowledge frontier (`internal/diagnostic/cat.go:1`, `improve.md:27` 30–45 min, covering set + info-gain). Entry: `/onboard` welcome (`onboard/page.tsx:56`), CTA on `Profile` (`profile:209`) labelled `Recommended` vs `Retake` (`profile:209`).  
_Avoid_: test, assessment, quiz (reserved)

**Seam** — Public boundary to test at (`tdd` `skills/skills/engineering/tdd/SKILL.md:1`). Pre-agreed seams for next bite: `LessonQuiz → SubmitAnswer` (`internal/engine/engine.go:398` `POST /api/answer` `server.go:286`).

**TaskLesson / TaskReview / TaskMultistep / TaskQuiz** — XP task types (`internal/xp/policy.go` effort-derived bases). Q2 locked: `*.word` and plain share the effort calibration (thresholds already differ); reviews cost half; quiz adds an assessment premium.  
_Avoid_: flat per-question XP, word as separate prereq depth (temporary node, future `Variants` fold via `enrichment.json` `improve.md:114`)

**Quiz (50 XP gate)** — Q3 was MA-verbatim `150 XP` (`improve.md:27`); rescaled to `50 XP` with the small-awards economy (same ~5-lesson cadence, smaller numbers — user-tuned economy supersedes MA fidelity, see ADR-020). Timed closed-book, `80%` difficulty via `computeDifficulty`, diverse recents, immediate remedial + retake (`internal/quiz/quiz.go:1`). Daily goal `10` (drift fix shipped: versioned backfill in `sqlite.go`). Banner: `Study → Take Test` + `Profile` due-reviews.
_Avoid_: 1–2 lesson gate, 30 XP shortcut

**XP** — `Award` in `internal/xp/policy.go` (`EffortBase 1–5 × timeMult 0.5–1.25 × streakMult 1+0.05*streak`): an effort-derived approximation, never exact time accounting. Miss 0, rush −1, diagnostic 0 XP. Daily goal `10`. Verified via `go vet` + `learn → answer → profile` `playwright`.

**GUEST_KEY** — `mathua_guest_id` persisted so guest `/profile` survives reload (`lib/auth.ts:4`).

**Landing graph (hero)** — WebGL concept map on `/` (`components/MathConceptGraph3D.tsx`), fed by build-time artifacts `public/data/concepts.graph.json` (nodes + indexed edges + domain counts) and `public/data/concepts.positions.json` (quantized `[x,y,z]`), generated by `scripts/build-graph.mjs` (`npm run graph:build`, also via `prebuild`). The corpus `data/concepts.json` stays out of First Load JS; only `data/graph.meta.json` (counts) is bundled. LOD tiers (far/mid/close) derive from world-units-per-pixel; labels render in one imperative DOM overlay; focus mode dims non-1-hop nodes/edges but never removes them.  
_Avoid_: bundling `concepts.json` into the landing bundle, per-node DOM/event listeners, client-side force layout

## Relationships

- DAG holds many Concepts; Concept has Prerequisites; `Available` filters by mastered
- Profile holds the Next task, the alerts, and the report (position/domains/activity/weakness); History holds attempted Questions; Study holds Lessons; Lesson holds Concepts + Problems
- Diagnostic compresses DAG → picks Concept via info-gain; Post-diagnostic → Profile; Profile holds the report, Profile → History for the attempts
- Study Lesson `→` TaskLesson (or TaskMultistep if `.word`) `→` SubmitAnswer `→` XP/Progress `→` Profile; at 50 XP `→` Quiz (TaskQuiz)

## Flagged ambiguities

- `Learning Mode` infinite loop removed (`session` now chooser `session/page.tsx:1` Diagnostic vs Study, then `Profile` hub); do not reintroduce as primary
- `Study` links that were wrong post-login (`login Skip → /study` etc) fixed to `→ /profile`; do not regress
- `skills/CONTEXT.md` is marketplace language (Issue tracker) — not Mathua; Mathua context lives here

## Decisions (ADRs, inline)

- ADR-001 Q1: Lock `Lesson=corpus`, `Study=library`, `Profile=hub` (2026-08-29) — prevents catalog-as-path relapse
- ADR-002 Q2: `*.word` as `TaskMultistep 15` seam, keep separate node pending `Variants` fold (2026-08-29)
- ADR-003 Q3: Quiz gate `150 XP` MA verbatim, not lesson-count shortcut (2026-08-29) — daily goal `30` makes `150/30=5d` honest — SUPERSEDED by ADR-020 (small-awards rescale, same cadence)
- ADR-004 Landing graph: keep three.js/R3F, drop drei; fetch graph payload/positions instead of bundling the corpus; deterministic domain-sector spherical layout (`lib/layoutDAG3D.ts`, O(n log n), 5k nodes ≈24ms); demand frameloop with auto-rotate stopping after first interaction (2026-09-11) — mobile First Load JS and 1k–5k scale without a renderer migration
- ADR-005 Grading contract (2026-09-27): one canonical dispatch `Engine.GradeAnswer` = custom `GradedGenerator.Grade` → 9-type `Router` (6 pure-Go graders) → SymPy. Every server path (`/api/answer`, `/api/study/answer`, quiz, goal diagnostic) must use it; a bare router call mis-grades the 32 custom-grader concepts (`5 R 3`, `3 sqrt(2)`, matrices, ratios). SymPy ships in the image (pinned `grading/requirements.txt`) and the image build self-tests, so `symbolic`/`polynomial`/`expression`/`complex` grading is present in production; there is **no** pure-Go symbolic fallback (the old `symbolicGrader` is dead code). Go fast paths grade exact-equal and constant-value expressions without the subprocess. Consequence: `expected == answer` must always grade correct.
- ADR-006 Grading never penalizes an infrastructure fault (2026-09-27): a grader that cannot run is "ungraded", never a student miss — no attempt, streak reset, weakness bump, or XP. `grader.Result.Unavailable` marks it. (The prod outage recorded ~32% of concepts as false misses because a missing SymPy runtime returned `correct:false`.)
- ADR-007 Study anchor is per-question (2026-09-27): practice stores the expected answer for **every** served question (keyed by question text, `SetStudyExpectedBatch`), not just the first. Anchoring only `questions[0]` guaranteed a mis-grade for any later question.
- ADR-008 Placement never destroys mastery (2026-09-27): `ApplyGoalResults` seeds only concepts still `UNSEEN`; a diagnostic/plan run must not overwrite streak, SM-2, attempts, or mastery of a concept the student has already started.
- ADR-009 Every served `Question` carries `grading_type`; every answer host shows the matching input (study, review, quiz, diagnostic). `Engine.GradeAnswer` is the one grader; `Result.Unavailable` is fail-soft everywhere (no attempt/streak/XP; client retries). `AvgResponseTime` includes incorrect attempts. `*.word` is `TaskMultistep 15` in both practice and study (implements ADR-002). Deferred: no repository transaction wraps progress+attempt+XP yet, and the study seam still accepts a client `expected` as a fallback when no server anchor exists.
- ADR-010 Grading data repair (2026-09-27): `mathua -repair-grading[-dry-run]` re-grades persisted `attempts` with `Engine.GradeAnswer`, flips false negatives (`UpdateAttemptCorrect`), and rebuilds `concept_progress` by replaying corrected history with the mastery/SM-2 primitives. `Result.Unavailable` attempts are skipped; XP is not rewritten. Always dry-run first.
- ADR-011 Structured choice input (2026-09-27): `multiple_choice` questions whose option list is embedded as `A) …` blocks (`lib/choices.ts` `parseChoices`) render tappable options (`components/ChoiceOptions.tsx`) in every answer host (diagnostic, quiz, review, study); picking one submits the option text, which `choiceGrader` grades by exact match. Non-parseable MC and all other types keep the free-text input. `SymbolPalette` gains a space key and the numeric hint names the fraction/mixed-number formats, so `4 1/10` is enterable on mobile. A server-side `Options` field on `generator.Problem` (rather than parsing the stem) is the intended follow-up.
- ADR-012 Postgres is a first-class store (2026-09-27): `internal/storage/parity_test.go` runs one identical scenario against SQLite and Postgres and requires the same observable result; CI runs it against a `postgres:16` service and `deploy` depends on it (`TEST_POSTGRES_DSN` gates the test). The parity test caught `GetDailyActivity` comparing a TEXT `timestamp` to `timestamptz` — now cast with `::timestamptz`. Known remaining divergence: Postgres `attempts`/`active_sessions` omit the SQLite foreign keys (align in a later pass).
- ADR-013 Corpus counts are generated, not hand-written (2026-09-27): `scripts/counts.py` computes concepts/domains/KP files/KP entries/subgoals/courses/diagrams from `data/` and rewrites the README's badges, sentences, and domain table (`--write`). CI and `make validate` run `--check`, which fails on stale README counts and on a denylist of superseded numbers (`641`/`580`/`284`/`1923`) anywhere in the docs. Counts had drifted every content wave; they now cannot.
- ADR-014 One diagnostic route (2026-09-27): the legacy `/api/diagnostic` + `/api/diagnostic/answer` (unauthenticated, trusted a client `correct` flag, no persistence, unused by the frontend) is removed, along with `Engine.SubmitDiagnosticAnswer`. `/api/goal/diagnostic/*` is the only diagnostic: it grades server-side via `Engine.GradeAnswer` against the stored problem. The legacy end-to-end test was migrated to the goal route.
- ADR-015 Stub lessons fail the gate (2026-09-28): 9 committed lessons were SEO/placeholder stubs (5 Algebrica bodies that never landed, 4 fraction word-problem templates); the audit only scanned `teaching/*.md` non-recursively and never `algebrica/`, so it missed all of them. The gate now scans recursively and flags tiny word-count + boilerplate files, validated to zero false positives against the corpus. Remedy: refetch Algebrica bodies via `scripts/refetch_algebrica.py` (one-time network, then committed), author word lessons to match their KP sections, and repoint semantically wrong mappings (`alg.systems.elimination`/`substitution` pointed at the Rouché–Capelli theorem page) with rewritten KPs. One lesson serving many concepts stays legal; the gate checks sections resolve, not 1:1 files.
- ADR-016 Currency-vs-math in the canonicalizer (2026-09-28): a `$…$` span with a digit is prose (escaped to literal `$`) only when it has no math marker and is either purely numeric or spaced *with a letter* (wordy price pairings like `$5 … saves … $10`). Factorial `!` is a math marker, and letterless lists (`1, 2, 3`) stay math — the old space-only rule leaked literal `$7!$`/`$1, 2, 3$` text into 24 lessons. Bare numerals (`$1$`) stay escaped per the bare-numeral gate; fix those in content, not here.
- ADR-017 Adaptive lesson loop (2026-09-29): `/learn` hosts the KP-interleaved loop; `Study` stays reference library, `Profile` task shelf deep-links to `/learn`. Pilot `Explanation`s (`arith.add`, `arith.div.remainder/long`, `frac.add.diff`, `frac.mixed.convert`, word variants) rewritten Given→Steps→Answer with substituted numbers. Prereqs are a soft dismissible banner via `GET /api/lessons/{id}/readiness` (no auto-redirect). Mastery is derive-only (`Engine.MasteryPct` + `MasteryBand`, no migration). Practice takes `?seed=&exclude=&difficulty=` so misses serve staged fresh variants. `mapping.json` kept (ingest scripts still read it).
- ADR-018 Attempt-first feed + task shelf (2026-09-29): `LearnStepper` is append-only — intro once, then each submit locks its card inline and the next question opens below; scrollback is the history, with a sticky tally header. No hint button and no gating buttons: post-mistake explanations render in the locked card, halt is a 3-miss safety net that appends an easier question plus prereq links. `masteryEstimate` (accuracy recent-weighted × difficulty × variation × time) drives advance/continue/intervene; 2-in-a-row is one input, not the rule. `selectShelf` proposes ≤5 eligible tasks behind a `SelectionPolicy` (v1 fixed weights: frontier-new, due review, weakness; XP shown per card); learner disposes. UI never names selection internals; critical path stays internal.
- ADR-019 Destinations + honest estimates (2026-09-29): destinations are named course bundles resolved to union prerequisite closures (graph stays source of truth); plans persist evidence/snapshots in `server_sessions(kind=study_plan)`, frontier derives live and is never stored. `internal/xp` owns award math (effort-derived 1–5 bases × time × streak; miss 0; rush −1; diagnostic 0 XP) and the estimator imports it — estimates can never duplicate constants. `EstimateWorkload` prices XP + time tracks (don't-knows cost reduced time with full remaining work, floored against gaming; quizzes/diagnostics are time-only, never XP debt). Pace is `min(goal, trailing-14d adherence)`; dates render as months, never promises. Goal changes never move quiz eligibility or mastery. Deferred: enforced per-path budgets, exam entity, CAT diagnostic, scored shelf policy, full misconception taxonomy.
- ADR-020 Small-awards economy (2026-09-29): XP rescales from flat 10/5/15/20 to effort-derived 1–5 bases (`EffortBase` from threshold seconds × difficulty; review halves, quiz premium +1); quiz gate 150→50, daily default 30→10, rush −5→−1, existing goals rescaled /3 via versioned v3 backfill (both stores). Cadence preserved (~5 lessons per quiz, ~a lesson a day). Bases are an effort-derived approximation, never exact time accounting. Deferred: retry multiplier, lesson accuracy bonus, continuous time-ratio rush.
- ADR-021 Study is reference-only detail (2026-09-29): LessonDetail shows title, concept chips, slim prereqs (badge + not-started/in-progress/mastered words, no percentages — percentages stay in Profile), one collapsed "Worked examples (N)" group (first expanded, identical bodies rendered once with combined labels, no pointer links), per-block ⋯ report menus with auto-attached block ids, and Start-learning CTAs. Footer, quiz banner, embedded practice, and the scroll-back button are gone from `/study` + `/concept`. No hidden results, no doing: reference explains, Learn teaches. Diagnostic prompts show iff new (`concepts_mastered === 0`) and incomplete, everywhere the rule applies.
- ADR-022 Reset clears evidence, keeps choices (2026-09-29): `Repository.ResetProgress` wipes progress/SM-2/speeds/attempts/sessions/quiz completions, study-scoped KV, XP, diagnostic flag, and league fields in one transaction on both stores; account, credentials, avatar, settings, goal, course, and `study_plan_prefs` (destination/deadline/pace) survive. Legacy single-record plans migrate lazily and idempotently. `POST /api/account/reset` requires the typed phrase, clears engine memory, orders the KV clear last, and is retry-safe. Settings danger zone gates on the phrase, offers CSV export first, and names the keeps (incl. leaderboard zeroing). Post-reset plans show a neutral fresh-start state until a new baseline lands.
- ADR-023 Single Next head over a ranked shelf (2026-09-30): supersedes the navigation model of ADR-017/018/021 (reference/doing split stands). DAG + `NextSmart` stay the source of truth; `selectShelfHead` returns `{next, alternatives}` with item 0 as the committed head, `selectShelf` is a flat wrapper, `selectNextUp` is the empty-policy fallback. `Learn` owns the head (`NextUpCard`); `Profile` shows a compact summary linking to `/learn`; `LearnStepper` done re-fetches the head and advances via `Continue: {label}` click (no auto-advance, alternatives present). `/concept` redirects to `/study?concept=`, `/session` redirects to `/learn`; nav `Start` renamed `Learn`. Study lists lessons in Kahn topo order. `TaskShelf` deleted.
- ADR-024 Progress moved off the hub (2026-10-01) — **partly superseded by ADR-025**: `/profile` was 586 lines doing five jobs — identity, a settings row, the task queue, activity, weaknesses, efficacy and per-domain mastery — which contradicted ADR-001 (`Profile=hub`) and ADR-023 (a compact summary). The report moved to `/progress`, ordered by the questions a learner asks: `PositionBlock` (mastered · unlocked · in progress · locked, plus the frontier the scheduler would serve next) → by domain → how you're doing → activity → struggles → recently unlocked. The hub keeps identity, the one Next task, the alerts and the new-user block, and links onward; it no longer fetches activity-adjacent report data beyond what `selectNextUp`/`selectShelfHead` need. Mastery counting is centralised in `lib/progress.ts` (`isMastered`, `prereqMet`, `countByDomain`, `countOverall`) after four copies had accumulated, and the report is deliberately not a percentage-of-657 — mastered-against-unlocked is the pair a learner can act on. `Engine.GetProgress` now applies `mastery.EffectiveStatus` on read so a decayed concept is `DECAYING` everywhere and not just to the scheduler; `prereqMet` accepts `DECAYING`, matching `scheduler.prereqsMet`, so decay never relocks successors. `/progress-card` renamed `/history` (`AttemptList`), because the sidebar's "Progress" entry pointed at a mistake log — the label was the bug. Cohort analytics stay on `/docs/efficacy`, never on a learner's own report. Deferred: persisting the diagnostic placement so `FrontierLabel` survives the session, and an explicit exit for the `/session` + `/concept` stubs.
- ADR-025 The report lives on the hub (2026-10-01): ADR-024 moved the report to `/progress` to honour ADR-001/023's "compact hub". In use that was wrong: a learner opening their own page got a task queue and an alerts column and had to go elsewhere to answer "how am I doing", and the hub stopped being the thing it is named for. The five sections came back to `/profile`, ordered `Activity` → `By domain` → `How you're doing` → `Struggles` → recently unlocked, below the identity/Next/alerts block. `Activity` leads deliberately: the heatmap is the "I showed up" signal and is what many learners open the page for. Restored by hand rather than by reverting the move, so the two things already decided against stayed out — the cohort first-pass-by-week chart (belongs on `/docs/efficacy`) and the daily-goal row that restated `ProfileStats`. `PositionBlock` came with it: it was the one part of the redesign that was new rather than moved, and it reads the same `head` the Next task does, so *where am I* and *what's next* cannot disagree. `/progress` is deleted; the sidebar entry became `History → /history`, which finishes the naming fix ADR-024 began. Kept from ADR-024 because they stand alone from the move: the `lib/progress.ts` extraction, `Engine.GetProgress` applying decay on read, `prereqMet` accepting `DECAYING`, and the `/history` rename. The lesson: ADR-023's "compact summary" was about not duplicating the Next head, not about hiding a learner's own numbers from them.
- ADR-026 A wipe must be unwritable, and must not lie about why (2026-10-03) — amends ADR-022: reset and delete only wiped the database, but `diagSessions` and `quizSessions` live in `Server` memory and the janitor swept them by age after an hour. A learner who reset and then reopened the tab they had left mid-diagnostic got their record back, because `handleGoalDiagnosticAnswer` re-inserts the attempt (`EnsureSession` + `RecordAttempt`) and `handleQuizAnswer` writes `concept_progress` and XP via `SubmitQuizAnswer`. Worse on Postgres: SQLite's `sessions` FK made `EnsureSession` fail and so accidentally shielded deletion, but Postgres omits those FKs (ADR-012), so **delete left real `attempts` rows for an identity that no longer exists**. Both handlers now call `Server.dropStudentLiveSessions` after the engine succeeds, so a stale answer is refused with 404 instead of rewriting the wipe; the age janitor stays for genuinely abandoned tabs. Second half: both handlers collapsed *every* engine error into `400 "confirmation phrase does not match"`, so a database refusal reached the learner as "you typed the wrong words" — unsendable advice, since the phrase was correct. `ErrResetPhraseMismatch`/`ErrDeletePhraseMismatch` are exported and matched with `errors.Is`; a real fault is now 500 and logged. Client-side, `resetAccount`/`deleteAccount` used `res.text()`, putting a literal `{"error":"…"}` in the danger zone; both now use the existing `throwWithResponse`. Also: `DeleteAccount` tracked the password requirement as a boolean, so a failed `getMe()` hid the field and the server's 401 `current password is required` had no input to satisfy — it is a tri-state now, showing the field but not requiring it when unknown, and the field's accessible name is distinct from the change-password field on the same page. Root cause of all of it was coverage: `POST /api/account/reset` had **no HTTP-level test at all**, and `ResetProgress` had **no Postgres test** (`TestDeleteAccount_RemovesEveryOwnedRow` is excluded from CI by the `-run TestParity` filter). `ResetProgress` now runs against both stores. Unrelated but found en route: `TestDeleteAccount_RemovesEveryOwnedRow` leaked the `Next` row that claims the freed address, so any reused DSN failed on `uidx_students_email` — invisible in CI, which gets a fresh database.
- ADR-027 The self-check is a simplification, not an equivalence check (2026-10-03): the request was "tell the learner whether this looks equivalent to the answer". The client does not hold the expected answer, and shipping it to power a hint would make the hint an answer oracle and undo ADR-005, so `components/math/SelfCheck.tsx` shows only what the learner's **own** expression simplifies to (`1/2+1/3` → `5/6`, `\sqrt{x^2}` → `|x|`). **Reframed 2026-10-03 at the owner's direction** — the addendum's Section E specified a three-valued `true|false|undefined` with `undefined` rendering no feedback. The shape was already satisfied under different names (`equivalent|different|unknown`); what differed was the correctness-feedback framing, which is not implemented and is not planned. The contract is now stated in `equivalence.ts` and `docs/math-input.md`, and `test/selfCheck.test.tsx` asserts that **no** state renders a verdict, using a real pair for each — `x²+2x+1` vs `(x+1)²` is `equivalent`, `2^10` vs `1024` is `different`, `\sqrt{x²}` vs `x` is `unknown`. Note `2x+3` vs `x²+2x+1` is `unknown`, not `different`: CE declines rather than guess, which is what makes `unknown` load-bearing. Measured while building it: `isEqual` returns `undefined` for the symbolic identities that matter (expanded vs factored, every trig identity), `isIdenticallyEqual` is the only call that can *refuse* — correctly declining `\sqrt{x^2}` vs `x` — but also declines to call `2x+3` and `2x+4` different, so a hint built on it must be able to say "I don't know"; `simplify` is the tie-breaker and is what makes trig work. Compute Engine is **788 kB gzip** (4× MathLive), so it is dynamically imported (+1 kB on routes with the editor, +0 elsewhere, never in initial JS) and skipped entirely when `navigator.connection.saveData` is set or the type is 2g — a one-line hint is not worth someone's data allowance. Rendering it is not the main difficulty; the arithmetic guard is: CE parses prose as a product of letter-variables and calls it valid, so only input containing an operator/digit/power/radical is ever sent. Two incidental findings recorded in `docs/math-input.md`: importing CE silently switches on MathLive's MathJSON paste (CE registers `globalThis[Symbol.for("io.cortexjs.compute-engine")]`, asserted in `test/equivalence.test.ts`), and CE 0.147's real MathJSON differs from its documentation — `Sqrt` survives canonicalisation and `x^2` stays `Power`, so a Go grader written to the docs would fail on most inputs. Also fixed en route: `MathLiveField`'s `emit` was a `useCallback` over `onChange`, so a host passing a fresh arrow every render re-ran the effect that pushes the host's value in, wiping what the learner had just typed; `emit` is stable via a ref and the effect keys on `value` alone. Reverting is one file (`SelfCheck.tsx`); nothing else in `components/math/` imports it.
- ADR-028 A corpus checker must state what it did not check (2026-10-03): `web/next-app/scripts/normalize-latex.mjs` (`make latex-normalize`) runs all 46,872 math spans in the lesson corpus through Compute Engine, because `test/latexCorpus.test.ts` proves KaTeX can *render* every lesson and KaTeX guesses at malformed input, so it is a weak signal. Four findings, each of which was a bug before it was a rule: spans must come from `cmd/latexdump -spans` (new flag) over the canonicalized body via `latexnorm.Scan`, because a dollar can be a delimiter or a currency amount and a regex reports every "$5 and up" as broken; **`ce.parse` is total and does not throw** — a syntax error returns a tree containing `["Error", reason, …]`, so a try/catch reports a corpus with thousands of broken spans as clean, which is worse than no report because it is a confident lie; **a parse failure is not a defect** — CE is a numeric CAS and this corpus is abstract algebra, topology and group theory, so it declines to type `U \times F` as `incompatible-type: number, function` after parsing it perfectly, and ~1,600 spans fail only because CE lacks a command, so reasons are bucketed `syntax` / `not-numeric` / `ce-gap` and only the first is reported; and **the buckets must reconcile** to the corpus total with an exit-2 on mismatch, because that assertion is what caught two earlier versions reporting "20,549 of 46,872" while reporting success, and the summary states `checked_pct` because a checker that quietly covers 44% of its input is not a clean bill of health. - ADR-038 Mastery is decided by evidence, and the ladder is three different questions (2026-10-04): completes ADR-037's deferred work. Mastery required `streak >= required_streak && avg time <= threshold` at **all three** tiers, and the engine resets the streak on every advance, so **459 of 657 concepts needed 30 consecutive correct answers** — 15,774 answers and ~130 hours for the corpus, median 12 min per concept, and a **4.2%** chance of completing a run in one sitting at 90% per-answer accuracy. One miss zeroes the streak. A floor of **6** was then set deliberately: `MasteryEvidenceFloor` is a minimum on *how much* evidence, not a demand for six consecutive correct answers, and `internal/mastery/measure_test.go` measures the cost rather than assuming it — six profiles (perfect, slow, one-miss-in-eight, 80% correct, slow-but-right, starts-rough) against all eight real corpus `avg_time_seconds`, and every one masters in exactly 6, so median/p25/p75/min/max are all 6. **Amended 2026-10-05 — two claims in the above were wrong, and both are recorded rather than quietly deleted.** (a) This ADR reported that "a sweep from 40% to 100% accuracy reports *every* level masterable and `MasteryThreshold` 0.6 is decorative". **It does not.** The sweep's test profile was `i%20 >= 12` — twelve wrong, then eight right — so a six-attempt window eventually landed entirely inside the clean run and reported mastery for a learner who was wrong 60% of the time. With evenly-distributed accuracy (`correctAt(i, n, k)` in `measure_test.go`) the threshold binds cleanly: **60%, 80% and 100% master in exactly 6 answers; 0%, 20%, 40% and 50% never master at any length.** `MasteryThreshold` 0.6 is kept unchanged — it was right, and the measurement was wrong. The lesson generalises past this file: *a probe's period is not the model*, and a synthetic pattern can manufacture a finding about the thing it is probing. (b) This ADR said variety "cannot veto". Precisely: the 0.15 bonus is large enough to flip the outcome **at the margin** — a 60%-accurate learner masters on varied instances and does not on identical ones — while leaving an 80%-accurate learner free to master on a generator that never varies. That is a *weight*, not a veto, and the property that matters is that no amount of demonstrated competence becomes **unreachable**; the `Instances >= 2` gate this replaced made a concept permanently unmasterable, which is a different and much worse failure. Both boundaries are now asserted rather than asserted-about: `TestVarietyRaisesTheBarWithoutBlockingMastery` and `TestMeasureAccuracyBandThatStillMasters`. The three knobs (`MasteryThreshold` 0.6, `MasteryEvidenceFloor` 6, the `varietyBonus` cap 0.15) sit together in one file. Floor of **6** is confirmed as the right gate for *leaving active teaching*: it is not a claim about durable retention, and the brief's own framing is that mastery means "demonstrated enough to exit the teaching loop". Making it larger on retention grounds would smuggle in the deferred spaced-retention system through the acquisition gate. The transition logic that ADR-038 left duplicated now has one authority: `Engine.applyGradedAttempt`, called by both `SubmitAnswer` and `submitAnswerWithTask`, so `Machine.Next` appears once in the codebase. Status still only moves forward, so mastery remains an exit. **Three things this change had to fix that were not in the brief.** (1) Difficulty was never persisted, so the server had strictly less evidence than the client: it computed one per question, passed it to the generator and dropped it. Now `attempts.difficulty` and `active_sessions.difficulty`, nullable and never backfilled, sourced from `activeSession.questionDifficulty` rather than the client; the NULL/non-NULL pair is covered by the ADR-012 parity test, which run against a real `postgres:16` caught two things a SQLite-only check cannot — a missing twelfth argument that made **every Postgres attempt write silently fail** (the test discarded the error with `_ =`), and a SQLite upsert left with `VALUES ()` by a regex assuming `$n` placeholders. (2) A gate on a derived signal made mastery **unreachable**: `EnoughForMastery` first also required two distinct problem instances, and a generator whose question text does not vary holds that at 1 forever. Variety now *scores* and cannot veto — a gate on a signal you do not fully control can lock a state. (3) The decay clock was gated on the rule being replaced: `LastReviewed` was set only on `streak >= required && avg time <= threshold`, a proxy for "a tier was just advanced" back when that was what advancement meant, so a concept could reach MASTERED with a streak of 1, leave `LastReviewed` nil, and read as fully decayed — the tests caught the ladder climbing **through DECAYING**. The clock now starts on tier attainment. The transition logic had also existed **twice**, `SubmitAnswer` and `submitAnswerWithTask`, one copy per answer host, and a quiz answer would have graded differently from a study answer; both now call `applyGradedAttempt`, leaving attempt-row recording and source classification to the host. `GetRecentAttemptsForConcept` is new because the window is read per graded answer and `GetAttemptsForStudent` returns everything. **Deferred:** spaced attainment *within* acquisition still needs a persisted `tier_attained_at`, as ADR-037 recorded; nothing here depends on it, and the ladder now makes that gap cheap to close later.
- ADR-039 Difficulty belongs to the question, not to the host that graded it (2026-10-05): ADR-038 left a hole it could not see, and it was a correctness bug rather than a design gap. **The number is the argument:** `BuildEvidence` set `difficultyTerm = 1.0` when an attempt carried no difficulty, with the comment "the term is dropped entirely rather than assumed, so old attempts are neither rewarded nor punished for it". Dropping a *multiplier* means multiplying by 1.0 — the top of the range — so a missing value was credited as *the hardest question the engine could have asked*. It was not cosmetic: at 50% accuracy the unknown-difficulty score was **0.65 and cleared `MasteryThreshold`, while the same attempts at difficulty 0.6 scored 0.57 and did not.** A learner could pass the mastery bar on one surface and fail it on another for identical answers. A pre-existing test named `TestBuildEvidence_UnknownDifficultyIsDroppedNotZeroed` asserted `score == 1.0`, so the wrong behaviour was pinned by a name that described it accurately and believed it correct — the same failure mode as ADR-035's keycap that typed its own name, one layer up. **Two causes, one symptom.** (1) *Plumbing:* difficulty went **into** `GeneratorContext` and stopped there — `generator.Problem` did not carry it back out, so every surface that generated a question and later graded it had to thread the value by hand, and two of three hosts did not. `SubmitAnswer` read it off `activeSession`; `submitAnswerWithTask` (which serves **both** the Learn loop and quizzes) passed a literal `0`; and the diagnostic recorded its attempt row directly in `server.go` with no difficulty at all. So **the main Learn loop was the host with no difficulty**, not the quiz — the opposite of where this was reported from. `Problem.Difficulty *float64` is now stamped by `Registry.GenerateContext`/`BatchGenerateContext`, which makes it structurally impossible to generate a question without its difficulty; `engine.Anchor` carries it for study, because the anchor is already the durable "what was served" record and is authoritative over the expected answer for the same reason; quiz reads `sess.LastProblem.Difficulty`; the diagnostic stamps it on the attempt row it writes. The chain is the one CONTEXT intended: generation → question metadata → grading → `gradedAttempt` → `applyGradedAttempt` → mastery. (2) *Scoring:* unknown is credited at `mastery.NeutralDifficulty = 0.55`, which is **not chosen** — it is what `difficultyFromWeakness` serves when it has no information about the learner (weakness defaults to 0.5, so `0.3 + 0.5 × 0.5`), and `TestNeutralDifficultyMatchesEngineDefault` fails if the serving side and the scoring side ever drift apart. `gradedAttempt.difficulty` became `*float64` so "unknown" is a value the caller must choose rather than a `0` reinterpreted downstream; that overloading is precisely what hid the bug. **What this is not:** `applyGradedAttempt` does not guess or re-derive difficulty — recomputing from the learner's *current* weakness would credit an attempt with the difficulty a **future** question would get, which is a different claim from the one they answered, so the quiz parameter is passed from the served problem instead. `TestStudyAndQuizProduceEquivalentMasteryEvidence` drives both hosts with the same questions, outcomes and difficulty and requires the persisted rows **and** the assembled evidence score to match; `TestUnknownDifficultyIsNotMoreGenerousThanKnown` and `TestUnknownDifficultyHostIsNotMoreGenerous` assert the property directly. All three were confirmed to fail against the pre-fix shape, so none of them is a guard that passes vacuously. **Mastery and retention stay separate, and this change is what makes that safe to assert:** `BuildEvidence` takes only attempts and the concept's thresholds — no clock, no "last reviewed" input — so `TestEvidenceHasNoSpacingTerm` can show evidence scores identically regardless of age, and `TestMasteryIsNeverLostToBadEvidence` shows six consecutive misses cannot un-learn a mastered concept. A learner who demonstrated a year ago demonstrated what they demonstrated then; whether they still can it is the deferred `tier_attained_at` question, and `MasteryPct` keeps decay as colour on a full bar so it never reads as loss of attainment. `questions.difficulty` is `NOT NULL DEFAULT 0.5`, so curated rows contribute a real value too — no third "unknown" population was left behind. **Deferred, and stated rather than faked:** `web/next-app/lib/progression.ts:masteryEstimate` is a **second** model and does not match this one — it weights difficulty per attempt rather than by the mean of the correct attempts, uses a fixed 60s time threshold rather than the concept's own, and has no unknown-difficulty case at all (`difficulty: number` is required), which is why this change creates no *new* browser/server divergence. It still feeds `LearnStepper`'s `advance` decision and its header band, so the two disagree at the margin. The server ladder is authoritative for progression, so that is a display-consistency problem rather than a correctness one, and unifying the two formulas is its own piece of work.
