# ADR-046: A mastery assessment verifies evidence; it does not write mastery

*2026-10-06*

**the "50 XP gate" is not a gate.** Four findings, all read rather than assumed. **(1) There is no PASS/FAIL anywhere.** `handleQuizAnswer` calls `RecordQuizCompletion` the moment `IsComplete` (`server.go:3417`), and `IsComplete` is `s.Index >= len(s.Order)` — it asks whether the *question list ran out*, not whether anything was answered correctly. So the XP baseline resets on **completion, pass or fail**, and a learner who scores zero clears the gate by finishing. The skip path is slightly better (`server.go:3517`, only when `HasAttempts`) and no better in kind. **(2) Retakes are unlimited by construction.** `retake_available: true` is a literal in both completion responses (`server.go:3220`, `3318`); there is no server state behind it to limit anything. **(3) `QuizDue` gates nothing.** It is read in exactly three places — `scoring/updater.go:122` sets the badge, `scheduler/recommend.go:183` prepends the recommendation, `engine/recommend.go:110` feeds that flag back in — and no progression path consults it. The dashboard said "recommended" and the scheduler treated it as an override, which is what made 50 XP the de facto authority. **(4) The machinery for a real assessment is half-built.** `quiz.Session` already carries `Order []*concepts.Concept` and `Attempts []Attempt{ConceptID, Correct}` (`quiz/quiz.go:13-28`), so the assessed concept set and per-concept correctness are already recorded — in memory, on `Server.quizSessions` (`server.go:162`), which ADR-026 already flagged as the reason a wiped learner could get their record back. And quiz answers already flow `SubmitQuizAnswer` → `submitAnswerWithTask(..., TaskQuiz, ...)` → `applyGradedAttempt`, so an assessment **already contributes mastery evidence** through the ADR-038 ladder. What is missing is the judgement, the persistence, and the boundary.
