# ADR-046: A mastery assessment verifies evidence; it does not write mastery

*2026-10-06*

**the "50 XP gate" is not a gate.** Four findings, all read rather than assumed. **(1) There is no PASS/FAIL anywhere.** `handleQuizAnswer` calls `RecordQuizCompletion` the moment `IsComplete` and `IsComplete` is `s.Index >= len(s.Order)`, it asks whether the *question list ran out*, not whether anything was answered correctly. So the XP baseline resets on **completion, pass or fail**, and a learner who scores zero clears the gate by finishing. The skip path is slightly better (`handleQuizSkip`, only when `HasAttempts`) and no better in kind. **(2) Retakes are unlimited by construction.** `retake_available: true` is a literal in both completion responses, in `handleQuizAnswer` and in `handleQuizSkip`; there is no server state behind it to limit anything. **(3) `QuizDue` gates nothing.** It is read in exactly three places, `scoring/updater.go:122` sets the badge, `internal/scheduler/recommend.go:301` prepends the recommendation, `internal/engine/recommend.go` feeds that flag back in, and no progression path consults it. The dashboard said "recommended" and the scheduler treated it as an override, which is what made 50 XP the de facto authority. **(4) The machinery for a real assessment is half-built.** `quiz.Session` already carries `Order []*concepts.Concept` and `Attempts []Attempt{ConceptID, Correct}` (`quiz/quiz.go:13-28`), so the assessed concept set and per-concept correctness are already recorded, in memory, on `Server.quizSessions` (`server.go:162`), which ADR-026 already flagged as the reason a wiped learner could get their record back. And quiz answers already flow `SubmitQuizAnswer` → `submitAnswerWithTask(..., TaskQuiz...)` → `applyGradedAttempt`, so an assessment **already contributes mastery evidence** through the ADR-038 ladder. What is missing is the judgement, the persistence, and the boundary.

**Amended 2026-10-25: scheduling is enforced, assessment is not.** Stage 1 closes finding (3) for session admission and narrows finding (2). `handleQuizSession` now asks `Engine.QuizDue` before it creates a routine mastery check for an identified learner, answers 409 when the gate is not earned and returns the learner's live run instead of creating a second one. Creating, refusing or abandoning a session does not move the XP snapshot; only the existing completion path does. The anonymous demo (no token, no student id) stays ungated because it writes no XP and no mastery, so it is not a bypass of an identified schedule. Nothing else in this ADR changes: there is still no PASS/FAIL, completion still resets the snapshot whatever the score and `retake_available` is still a literal. A retake is now available after the gate is earned again rather than immediately. The judgement, persistence and assessment boundary remain the later stages this ADR called for.

**Amended 2026-10-25: selection draws only from learned evidence.** Stage 2 narrowed the candidate pool `Engine.PickQuizConcepts` offers to an identified learner. A concept now needs a progress row that is not `UNSEEN`, that carries a graded attempt or `MASTERED` status and whose prerequisites `scheduler.EligibilityOf` satisfies. A placement-seeded row with no work behind it grants reachability but is not evidence, so it does not qualify. Weakness orders the pool, distinct subdomains are covered before a second concept from one subdomain and the latest quiz-sized window of quiz attempts is deferred while other candidates remain. When the gate is earned but no candidate qualifies, the endpoint answers 422 with its own message instead of falling back to the curriculum. Weak or decaying concepts are not excluded, because measuring them is the point. None of this writes mastery, changes the gate or creates a per-concept readiness threshold; the judgement and persistence stages remain open.

**Corrected 2026-10-25: mastery is not a routine-check candidate.** The Stage 2 paragraph above treated `MASTERED` as learned evidence and left decaying concepts in the pool. That conflated acquisition with retention. `docs/mastery-semantics.md`, ADR-038 and ADR-039 keep the two surfaces separate: a mastery check verifies that a concept was acquired, while a review verifies that mastered material is still retrievable. The product copy already said the check "covers what you just learned" and the review covers "concepts whose memory is fading". `Engine.PickQuizConcepts` now excludes stored `MASTERED` and `DECAYING` rows from the candidate pool. A mastered concept still satisfies its dependents' prerequisites through `scheduler.EligibilityOf`, so it unlocks the next concept without being assessed again. A `LEARNING` or `PRACTICING` concept with a graded attempt stays a candidate even when weak or due for review; weakness is what the check measures. The Stage 2 sentence that admitted `MASTERED` status or kept decaying concepts is superseded to that extent.

**Amended 2026-10-25: the clock is authoritative, the limit is not a hard stop.** Task 3 added `QuestionStarted` to `quiz.Session`, stamped by `NextQuestion` when the server serves a question. `handleQuizAnswer` measures from that stamp and uses the larger of the server measurement and the client's report, so a refresh or a manipulated client cannot make an answer look faster than the server observed. The persisted elapsed feeds `BuildEvidence` and TaskQuiz XP, so a late answer still counts as slow evidence and is still graded. No answer is rejected for exceeding `time_limit_seconds`: commit b70fd5c1 removed the visible countdown on purpose and kept the measurement, because time is a slow-answer threshold rather than a hard expiry. Unanswered questions keep the existing skip semantics (no attempt, no XP, no remedial), a fully skipped run does not move the XP snapshot and abandoned runs are still swept after an hour. No schema change was needed.

**Amended 2026-10-25: retake availability is the gate, not a literal.** Task 5 closes finding (2). `retake_available` in both completion responses is now computed by `quizRetakeAvailable`, which asks the same `Engine.QuizDue` the session endpoint asks. An identified learner who answered at least one question has moved the XP snapshot on completion, so the field is false and the next start request would receive the existing 409. A fully skipped identified run records no attempt, does not call `RecordQuizCompletion` and keeps the field true because the gate was never spent. A run with one answer and a skip has an attempt, so it moves the snapshot and reports false. Anonymous runs report true because they write no XP and remain ungated. A storage failure reports false rather than promising a retake the server would reject. The completion screen reads the field: it offers `Retake Quiz` only when true and otherwise offers `Keep learning` with no threshold shown. The quiz briefing no longer promises immediate worked solutions or an anytime retake. The remedial list now says `Focus next in Learn` because its links already went to `/learn`. Remediation itself, `BuildEvidence`, `Machine.Next`, grading and XP accounting are unchanged.
